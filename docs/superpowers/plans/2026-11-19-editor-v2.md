# Редактор сценария v2 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сделать редактор сценария понятным людям без опыта программирования: поток слева направо, блоки разной формы, добавление шагов «+» и перетаскиванием, удобные связи, окно блока «Вход — Настройки — Выход», конструктор условий и выражения с подсказками.

**Architecture:** Только `apps/web` (редактор) плюс небольшие чистые функции в `@chatbot/model` (анализ переменных). `apps/web` получает право импортировать `@chatbot/engine-core` (чистый браузерный пакет), чтобы проверять выражения и показывать предпросмотр шаблонов теми же функциями, что и движок. Формат сценария (`formatVersion: 1`) не меняется.

**Tech Stack:** React 18, `@xyflow/react` 12, shadcn/ui + Tailwind v4, lucide-react; новые зависимости web: `@uiw/react-codemirror`, `@codemirror/autocomplete`, `@codemirror/view`, `@codemirror/state`, `@codemirror/language`, `@dagrejs/dagre`.

**Spec:** требования пользователя после ручной проверки 19.11 (ниже, раздел «Требования»); референс — n8n (поток слева направо, «+» на выходах, наведение на связь, панель «Что дальше?», конструктор условий, окно узла «Input — Parameters — Output», «Add first step»); `VP-chatbot/stack-and-plan.md` п. 1.9 (язык дизайна), п. 2.4–2.5 (шаблоны и выражения), п. 3.3 (формат сценария).

## Требования (от пользователя, 19.11)

1. Соединять блоки неудобно; связь нельзя удалить без клавиши Delete.
2. Нет подсказок при вводе выражений и кода (как в n8n).
3. Блок из левой панели нужно уметь перетащить на холст, а не только кликнуть.
4. Интерфейс в целом недружелюбен для людей, которые будут сами собирать ботов.
5. Связи запутываются даже при ровной раскладке (вход сверху, выход справа снизу).
6. У блоков разных типов своя форма — по ней сразу понятно, к чему блок относится.
7. Приветствие на пустом холсте, как «Add first step…» в n8n.
8. Окно блока: слева «Вход», в центре настройки, справа «Выход».
9. На концах связей — стрелки; при наведении на связь — кнопки «добавить блок» и «удалить связь».
10. Блоки привязываются к сетке, а не двигаются свободно.
11. Над блоком при наведении появляется маленькое меню действий.

Решения пользователя: поток **слева направо**; условия — **конструктор + режим «Выражение»** с подсказками; настройки блока — **модальное окно как в n8n**; делаем **сейчас, отдельным планом** до спринта 2.

## Global Constraints

- Все тексты интерфейса — на русском, в `apps/web/src/i18n/ru.ts`; комментарии и коммиты — на русском; коммиты без `Co-Authored-By` и подобных строк.
- Формат сценария не меняется; данные узла React Flow содержат только поля блока модели (схема молча отбрасывает лишние ключи). Состояние интерфейса (конструктор условий, тестовые значения) в сценарий не сохраняется.
- Правила архитектуры: `apps/web` из пакетов проекта импортирует только `@chatbot/model` и `@chatbot/engine-core` (правило `web-only-model` переименовать в `web-allowed-packages` в задаче 1); циклов нет; `pnpm arch` зелёный.
- Новые зависимости — только перечисленные в Tech Stack, добавляет их задача 1.
- Цвета — токены темы shadcn; акцентный цвет только у блоков (из `BLOCK_META`); светлая и тёмная темы.
- Все действия доступны мышью; клавиатура — дополнительно. Ничего не удаляется без возможности отменить (Ctrl+Z).

## Review Focus

1. Удаление связи мышью (кнопка на связи) и отмена удаления Ctrl+Z работают; Delete в полях ввода окна блока не удаляет узел.
2. Связи не «закручиваются»: при стандартной раскладке слева направо ребро идёт от правого края источника к левому краю цели; кнопка «Упорядочить» даёт граф без перекрытий.
3. Конструктор условий ↔ выражение: условие из конструктора сохраняется строкой, которую принимает движок (`parseExpression` из engine-core); выражение, которое конструктор не умеет показать, открывается в режиме «Выражение» без потери текста.
4. Подсказки: в полях выражений и шаблонов (`{{`) список переменных, доступных именно в этом блоке (записанных блоками выше по графу), плюс `env.*`; ошибка синтаксиса видна сразу под полем.
5. Перетаскивание из палитры кладёт блок в точку отпускания (по сетке); «+» на выходе создаёт блок, уже соединённый с этим выходом; кнопки меню блока и связи не мешают перетаскиванию и соединению.

- Produces: `BlockDialog` — большое модальное окно (≈ 90 % экрана, shadcn Dialog), заголовок: иконка, редактируемое название, тип; три колонки:
  - **Вход** — переменные, доступные в блоке (`availableVariables`), с источником («из блока „Ввод имени“») и полем «тестовое значение»; переменную можно перетащить в поле настроек (вставляет `{{имя}}` в шаблон или имя в выражение/конструктор); тестовые значения живут только в памяти окна.

  - **Выход** — что блок отдаёт дальше: записываемые переменные (`blockWrites`), список выходов с подписями и названием блока, куда ведёт связь (или «не подключён»); предпросмотр с тестовыми значениями: для сообщений/вопросов — текст после `render`, кнопки вариантов; для Условия — какой выход сработает (`evaluate`); для HTTP — итоговый URL и заголовки (секреты маской).

- Produces: конструктор условий для блока «Условие»: строки «переменная — оператор — значение» (операторы по-русски: равно, не равно, больше, меньше, не меньше, не больше, пусто, не пусто), объединение «все условия (И)» / «любое (ИЛИ)»; `conditionToExpression(model): string` и `expressionToCondition(expr): model | null` (null → режим «Выражение»); переключатель «Конструктор / Выражение» как «Fixed / Expression» в n8n. «Пусто» = `x == ""`, «не пусто» = `x != ""`; строковые значения в кавычках с экранированием, числа — как есть.
- Produces: для «Присваивание» — поле `ExpressionInput` с подсказкой примеров (`tries + 1`, `"Здравствуйте"`).

- [ ] **Step 1: Тесты** — `conditionToExpression` ↔ `expressionToCondition` для И/ИЛИ, чисел и строк с кавычками; выражение `(a < 3) && !b` → `null` (режим «Выражение», текст сохранён); выражение из конструктора проходит `parseExpression`; `BlockDialog`: колонка «Вход» показывает переменные блоков выше по графу; «Выход» для Условия с тестовыми значениями показывает выход «да»; Delete в поле ввода не удаляет узел.
