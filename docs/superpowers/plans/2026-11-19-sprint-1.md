# Спринт 1 и каркас модулей — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Монорепозиторий «Конструктора чат-ботов» с работающим функционалом спринта 1 (движок без HTTP, консольный чат, HTTP-клиент, вход и проекты, эхо-бот Telegram через очередь, холст редактора) и каркасом всех остальных модулей модели — чтобы к 02.12 построить диаграмму модулей по реальному коду.

**Architecture:** pnpm-монорепозиторий. Чистая логика (формат сценария, движок, выражения, шаблоны, jsonPath, шифрование) — в пакетах `packages/*` без ввода-вывода; приложения `apps/api` (NestJS, REST + webhook), `apps/engine` (NestJS без HTTP, воркеры BullMQ) и `apps/web` (React SPA) подключают их. Путь события: Telegram → api → очередь (16 разделов, Redis) → engine → PostgreSQL → ответ в Telegram.

**Tech Stack:** Node.js 22, TypeScript strict, pnpm 9 (corepack), NestJS 10, Prisma 5 + PostgreSQL 16, BullMQ 5 + Redis 7, undici 6 + p-retry 4, grammY, jsep, zod 3, argon2, React 18 + Vite + React Flow (`@xyflow/react` 12) + TanStack Query 5 + shadcn/ui + Tailwind CSS + lucide-react, Vitest, dependency-cruiser, GitHub Actions.

**Spec:** `VP-chatbot/stack-and-plan.md` (разделы 1–3 — решения и алгоритмы, 5.4 — состав спринта 1); `VP-chatbot/Use cases.pdf` (сценарии UC); диаграммы `VP-chatbot/class-diagrams/Классы - BCE.png` и `Классы - блоки сценария.png`.

## Global Constraints

- Идентификаторы в коде — на английском, имена классов и методов — как в модели (BCE и «блоки сценария»). **Комментарии в коде и сообщения коммитов — на русском.** Коммиты без строк `Co-Authored-By` и подобных.
- Тексты интерфейса и системные сообщения бота — на русском; все строки web лежат в `apps/web/src/i18n/ru.ts`.
- Имена пакетов: `@chatbot/model`, `@chatbot/engine-core`, `@chatbot/vault`, `@chatbot/db`, `@chatbot/queue`, `@chatbot/api`, `@chatbot/engine`, `@chatbot/web`.
- Пакеты `packages/*` не зависят от `apps/*`; `@chatbot/model` не зависит ни от одного пакета проекта; `@chatbot/engine-core` зависит только от `@chatbot/model`; `apps/web` из пакетов проекта импортирует только `@chatbot/model`. Циклов зависимостей нет.
- Все зависимости объявляет задача 1. Задача, которой нужна новая зависимость, останавливается со статусом NEEDS_CONTEXT. Исключение — задачи 11 и 12 (`shadcn add` может добавить пакеты Radix в `apps/web`).
- Порты: api `3000`, web `5173`, PostgreSQL `55432`, Redis `56379`. Переменные окружения — только из `.env` (в git — `.env.example`).
- Формат сценария — п. 3.3 спецификации, `formatVersion: 1`; поля блоков — диаграмма «Классы: блоки сценария».
- Лимит автопрохода — 100 шагов на событие (п. 2.3); 16 разделов очереди (п. 2.2); `attempts: 1` у заданий.
- Нереализованный метод каркаса бросает `new NotImplementedError('<Класс>.<метод>')` из `@chatbot/model`.
- **Работа в worktree:** скопировать `C:/D/SA/.env` (если есть, иначе `.env.example` → `.env`), `corepack pnpm install`, после задачи 5 — `pnpm --filter @chatbot/db db:generate`. Docker Compose — общий проект `chatbot` (одни контейнеры на все worktree); интеграционные тесты очищают свои таблицы сами и запускаются только через `test-lock`.
- Тесты: модульные `*.test.ts` (`pnpm test`, без Docker), интеграционные `*.int.test.ts` (`pnpm test:int`, последовательно). Тесты api и engine компилируются через `unplugin-swc` (метаданные декораторов NestJS). Тесты, поднимающие приложение, принудительно ставят `TELEGRAM_POLLING=0`.
- Скрипты (`chat`, `p1`, `seed:dev`) лежат в `<пакет>/scripts/` и запускаются через `tsx`; примеры сценариев — в `<пакет>/examples/`; оба вне `src`.
- BullMQ запрещает `:` в собственных `jobId` — разделитель в `jobId` везде `-`.

## Review Focus

1. Выражение автора с доступом к полю или вызовом (`constructor.constructor("…")()`, `a.b`, `f(1)`) — ошибка «недопустимое выражение», код не исполняется (задача 3).
2. Пользователь вводит текст `{{env.API_KEY}}` — он не раскрывается при выводе: подстановка в один проход (задача 3).
3. Редактор сохраняет переход на удалённый блок или два перехода из одного выхода — API отвечает 400 с описанием, сценарий в базе не портится (задачи 2 и 9).
4. Цикл из блоков без ожидания — на 101-м шаге диалог FINISHED и системное сообщение «Диалог остановлен: сценарий зациклился» (задача 7).
5. Нажатие устаревшей кнопки от прошлого вопроса — игнорируется, текущий вопрос отправляется заново, без падения (задача 7).
