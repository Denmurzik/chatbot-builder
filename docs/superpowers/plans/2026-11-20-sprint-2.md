# Спринт 2 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сценарий из редактора публикуется в бота, работает в Telegram на сервере `chatbot.nsumonkey.top` и ходит в тестовый API записи к врачу; два бота одного сценария изолированы.

**Architecture:** Чистая логика HTTP-блока (разбор ответа, стратегии ошибок, отбрасывание устаревших ответов, приостановка) — в `@chatbot/engine-core`; запись запросов, отправка и восстановление — в `apps/engine`; боты, окружения, подключение Telegram, проверка сценария и публикация — в `apps/api`; страницы ботов, окружений и панель проверки — в `apps/web`. Развёртывание — Docker Compose на VPS за уже работающим Nginx Proxy Manager (NPM), а не Caddy (решение пользователя 20.11: порты 80/443 на сервере заняты NPM).

**Tech Stack:** как в спринте 1 (Node 22, TypeScript strict, NestJS 10, Prisma 5, BullMQ 5, grammY, undici + p-retry, React 18 + React Flow + shadcn/ui + TanStack Query, Vitest). Новых npm-зависимостей нет.

**Spec:** `VP-chatbot/stack-and-plan.md` — п. 1.5 (восстановление), 2.1, 2.2, 2.3, 2.6–2.13, 3.1, 3.3, 5.4 (спринт 2). Решения пользователя 20.11: публикация и переопубликация переносятся из спринта 3 в спринт 2; HTTPS через NPM; на сервере — новые Telegram-боты, токены вводит пользователь сам.

## Global Constraints

- Комментарии в коде и сообщения коммитов — на русском; коммиты без `Co-Authored-By` и подобных строк. Имена классов и методов — как в модели (`docs/architecture/model-mapping.md`).
- Тексты интерфейса — в `apps/web/src/i18n/ru.ts`; сообщения ошибок API и системные сообщения бота — на русском.
- Новые npm-зависимости запрещены; нужна зависимость → статус NEEDS_CONTEXT.
- Правила слоёв (`pnpm arch`) не нарушать: `engine-core` зависит только от `model`; web из пакетов — только `model` и `engine-core`; приложения не импортируют друг друга.
- Секреты (токены, секретные переменные окружения, секретные заголовки) API никогда не возвращает в открытом виде — только `mask`; в журналы — маска. AAD: токен — `tokenAad(botId)`, окружение бота — `envAad(botId, name)`, окружение проекта — `envAad(projectId, name)` (как уже расшифровывает engine).
- Все маршруты API под `JwtGuard` проверяют владельца через `project.authorId`; чужой или несуществующий проект/бот → 404.
- Работа в worktree: скопировать `C:/D/SA/.env`, `pwsh -NoProfile -Command "corepack pnpm install"`, `pnpm --filter @chatbot/db db:generate`; Docker Compose общий (`pnpm infra:up` уже поднят). Полные прогоны (`pnpm lint; pnpm build; pnpm typecheck; pnpm test; pnpm test:int; pnpm arch`) — только через `test-lock`.
- Новая таблица или столбец — миграция Prisma с именем `YYYYMMDDHHMMSS_<смысл>` и добавление таблицы в `truncateAll` (`apps/api/test/test-db.ts`).
- Интеграционные тесты, которые сейчас утверждают `NotImplementedError` у реализуемых методов (`apps/engine/src/skeleton.int.test.ts`, `apps/api/test/skeleton.int.test.ts`), задача, реализующая метод, обновляет.
- BullMQ `jobId` — разделитель `-`, не `:`.

## Review Focus

1. Ответ HTTP пришёл после /start или переопубликации — отброшен, диалог не изменился, в журнале «ответ отброшен» (задачи 1, 2, 7).
2. Секретная переменная окружения: GET ботов/проекта и ответы PUT содержат только маску; PUT без нового значения сохраняет прежний шифротекст; переименованная секретная переменная без значения → 400 (задача 5).
3. Тот же токен Telegram подключают ко второму боту — 409 «Токен уже используется другим ботом», первый бот не затронут (задача 5).
4. Переопубликация, пока диалог ждёт ответа HTTP или ввода, — все диалоги бота FINISHED, следующее сообщение начинает новую версию с точки входа (задача 7).
5. Два превью-сеанса и бот с тем же `chatId` не делят контекст (задача 4).
