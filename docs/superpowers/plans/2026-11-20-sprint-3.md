# Спринт 3 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Автор проверяет сценарий в превью прямо в редакторе (чат через тот же движок, подсветка текущего блока, панель переменных, системные сообщения, перезапуск, тестовое окружение проекта), выгружает сценарий в JSON и загружает обратно; сценарий записи к врачу проверен сквозным тестом со сбоями API; документы и модель приведены к фактическому состоянию.

**Architecture:** Превью — канал PREVIEW того же движка (спринт 2: engine публикует `PreviewEvent` в Redis `preview:<chatId>`). В api — Socket.IO-шлюз: принимает ввод автора, ставит события в ту же очередь, подписан на `preview:*` и пересылает события в комнату сеанса. Экспорт/импорт — REST в api, формат = формат хранения сценария (п. 3.3) без секретов.

**Tech Stack:** как в спринтах 1–2. Новая зависимость: `socket.io-client` в `apps/web` (сервер `socket.io`, `@nestjs/websockets`, `@nestjs/platform-socket.io` уже есть в `apps/api`).

**Spec:** `VP-chatbot/stack-and-plan.md` — п. 1.10 (превью), 2.1 (событие превью), 2.3 (остановка на неподключённом выходе), 2.13 (экспорт без секретов), 3.3, 5.4 (спринт 3); UC-A-20…A-23, A-29…A-31. Решения пользователя: UI тестового окружения перенесён в спринт 3; YAML — после защиты.

- Комментарии и сообщения коммитов — на русском; без `Co-Authored-By` и подобных строк. Строки интерфейса — в `apps/web/src/i18n/ru.ts`; ошибки API — на русском.
- Новые зависимости — только `socket.io-client` в `apps/web` (задача 4) и в devDependencies `apps/api` для тестов (задача 2). Остальное — NEEDS_CONTEXT.
- Слои (`pnpm arch`): `engine-core` → только `model`; web → только `model` и `engine-core`; приложения не импортируют друг друга.
- Секреты никогда не уходят в ответы API, события превью и файл экспорта (кроме маски там, где она уже показывается).
- Все маршруты и шлюз проверяют владельца проекта (`project.authorId`), чужой/несуществующий → 404 (REST) или ошибка `forbidden` с отключением (Socket.IO).
- Путь Socket.IO — `/api/socket.io` (проходит через существующие прокси `/api/` в nginx и Vite; Vite-прокси включить `ws: true`).

## Review Focus

1. Два окна превью одного проекта (или двух авторов) не видят событий друг друга: события идут только в комнату своего сеанса (задача 2).
2. Чужой автор подключается к превью чужого проекта — отказ, событий не получает (задача 2).
3. Экспорт сценария с секретным заголовком — в файле нет ни значения, ни шифротекста; после импорта блок требует ввести секрет заново (задача 3).
4. Импорт битого или чужого формата (не JSON, другая `formatVersion`, переход на несуществующий блок) — 400 с понятным списком, сценарий проекта не изменился (задача 3).
5. Нажатие кнопки в превью после перезапуска (устаревшая кнопка) не ломает сеанс (задачи 2, 4).

### Task 2: api — Socket.IO-шлюз превью

**Files:**
- Create: `apps/api/src/preview/preview.gateway.ts`, `apps/api/src/preview/preview-subscriber.ts` (подписка Redis), `apps/api/test/preview.int.test.ts`
- Modify: `apps/api/src/preview/{preview.controller.ts,preview.module.ts}`, `apps/api/src/main.ts`/`configure-app.ts` (адаптер Socket.IO, путь), `apps/api/test/skeleton.int.test.ts`, `docs/architecture/model-mapping.md`

**Interfaces:**
- Consumes: `EventQueue.enqueue(event, jobId)`, `PreviewEvent`, `parsePreviewChatId`, канал `preview:<chatId>` (Task 1).
- Produces (namespace `/preview`, path `/api/socket.io`, аутентификация — cookie `session` при рукопожатии, тот же JWT, что у `JwtGuard`):
  - клиент → `start {projectId}` → сервер проверяет владельца, создаёт `sessionId` (uuid), `chatId = preview:<projectId>:<sessionId>`, кладёт сокет в комнату `chatId`, ставит `START_COMMAND`; ответ ack `{ chatId }` или `{ error }`.
  - `input {text}` → `TEXT_MESSAGE`; `button {callbackData}` → `BUTTON_PRESS` (`payload`, `sourceBlockId` из `callbackData` `<blockId>:<n>`); `restart` → `START_COMMAND`. Все — только для своего `chatId` (из состояния сокета, не из сообщения). `userId = author:<authorId>`, `channel PREVIEW`, `botId null`, jobId `preview-<sessionId>-<n>`.
  - сервер → `preview` с `PreviewEvent`. Один `PSUBSCRIBE preview:*` на процесс, маршрутизация по `chatId` в комнату.
  - отключение сокета — выход из комнаты; контекст в БД остаётся (очистка — не в этом спринте).
  - Заглушки `PreviewController` удалить; в `model-mapping.md` — `startPreview/sendInput/restartPreview` → события шлюза, `stopAtUnconnectedOutput` → поведение движка (системное сообщение + подсветка, Task 1).
  - Vite: `proxy: { '/api': { target: 'http://localhost:3000', ws: true } }` (файл `apps/web/vite.config.ts` — только эта строка).
- [ ] Int-тесты (клиент — `socket.io-client` в devDependencies `apps/api`, допустимое исключение): без cookie → отказ подключения; чужой проект → ack `{error}`; `start` → в очереди событие `START_COMMAND` с нужным `chatId`; `input`/`button`/`restart` → соответствующие события; `PreviewEvent`, опубликованный вручную в Redis `preview:<chatId>`, приходит только в свой сокет — второй сеанс его не получает. Движок в тестах api не поднимается (приложения не связаны).
- [ ] FAIL → реализация → PASS → коммит `feat(api): Socket.IO-шлюз превью`.
